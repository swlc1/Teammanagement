# Team Management Dashboard · Firebase 연결

GitHub Pages의 화면을 유지하면서 Firebase Authentication과 Firestore로 로그인 및 업무 데이터를 공유합니다. 별도 npm 빌드 없이 `index.html`, `sync-engine.js`, `firebase-backend.js`를 같은 경로에 배포합니다.

## 적용 순서

1. 이 변경사항을 `main`에 병합합니다. GitHub Pages 배포가 끝나면 `https://swlc1.github.io/Teammanagement/`를 새로고침합니다.
2. Firebase 프로젝트 `teammanagement-1a1f2`의 Firestore 규칙을 이 저장소의 `firestore.rules` 전체 내용으로 교체하고 게시합니다. 이전에 설정한 관리자 전용 규칙으로도 첫 관리자 확인은 가능하지만 팀장·팀원 운영에는 새 규칙이 필요합니다. GitHub에 규칙 파일을 올리는 것만으로 Firebase에 적용되지는 않습니다.
3. Authentication에 이미 생성한 관리자의 실제 이메일·비밀번호로 로그인합니다. `admin/admin123` 같은 기존 데모 계정은 사용하지 않습니다.
4. 관리자 문서는 `users/X5VfKprPWkgponOX3L1zPDmXn0K3`입니다. `role`은 문자열 `admin`, `enabled`는 boolean `true`여야 합니다.
5. 처음에는 업무 데이터가 비어 있습니다. 관리자 설정의 **기존 PC 데이터 가져오기** 또는 **백업 데이터 복원**으로 기존 데이터를 가져오거나 새 팀원과 업무를 등록합니다. 기존 브라우저 저장소는 자동 삭제하거나 업로드하지 않습니다. 예제 데이터가 섞였는지 확인한 뒤 가져오세요.

## 팀원 계정

1. `swlc` 관리자 계정으로 로그인하고 팀원정보에 팀원을 등록합니다.
2. 관리자 설정 → 로그인 계정 관리 → 해당 팀원의 **계정 생성**을 누릅니다.
3. 실제 이메일·초기 비밀번호·비밀번호 확인·표시 이름·역할을 입력하고 생성합니다. UID 입력이나 Authentication 콘솔의 사전 생성은 필요하지 않습니다.
4. 팀원에게 이메일과 초기 비밀번호를 전달하면 해당 계정으로 로그인할 수 있습니다.

관리자 화면에서 표시 이름과 역할을 수정하고 사용중지·사용허용·잠금·잠금해제·비밀번호 재설정 메일 발송을 처리합니다. 비밀번호는 업무 DB에 저장하지 않습니다. 계정 생성은 별도의 메모리 전용 인증 세션에서 처리하므로 관리자 로그인은 유지됩니다. 권한 등록 실패 시 방금 생성한 인증 계정도 취소하며 오류를 표시합니다.

계정 사용중지·잠금은 앱의 데이터 접근을 차단합니다. 기존 사용자의 이메일 변경이나 비밀번호 강제 지정에는 계정 소유자의 재인증 또는 신뢰할 수 있는 별도 관리 서버가 필요합니다. 현재 구성은 다른 사람의 이메일을 바꾸는 입력란을 잠그고 비밀번호는 재설정 메일을 사용합니다. Authentication 계정의 영구 삭제는 이 화면에서 제공하지 않습니다.

**삭제 버튼**은 시스템 로그인 권한을 회수합니다. 계정은 활성 목록에서 빠지고 사용중지·잠금 상태로 표시를 보관합니다. 팀원정보와 업무·일정·보고서 기록은 삭제하지 않습니다. 현재 로그인한 관리자 자신은 삭제할 수 없습니다. 아래 **삭제된 로그인 계정** 목록에서 기존 UID와 이메일의 로그인 권한을 복구할 수 있습니다. 같은 이메일로 새 인증 계정을 만드는 대신 복구를 사용하세요. 복구 시 사용중지와 잠금이 해제됩니다. Firebase Authentication 원본 계정의 영구 삭제는 별도 콘솔 처리가 필요합니다.

인증 계정만 있고 `users` 권한 문서가 없는 계정은 업무 데이터에 접근할 수 없습니다. 관리자 화면에는 권한 문서가 연결된 계정을 표시합니다.

| 역할 | 데이터 접근 |
| --- | --- |
| 관리자 | 업무 데이터 전체와 계정·권한 설정 관리 |
| 팀장 | 업무 데이터 관리와 상담·면담 조회. 계정·권한 설정과 팀원정보 수정은 관리자 담당 |
| 팀원 | 허용된 메뉴 데이터 조회. 편집 권한이 있는 메뉴에서 본인 담당 기록만 수정 |

상담·면담과 시스템 로그는 관리자·팀장에게만 제공합니다. 팀원에게 상담 메뉴를 표시하도록 설정하더라도 상담 원문은 읽을 수 없습니다. 팀원은 자신의 휴가를 `신청` 상태로 등록하며 승인 상태 변경은 관리자·팀장이 처리합니다. 메뉴별 데이터 조회는 해당 메뉴의 Firestore 컬렉션 단위입니다. 메뉴를 숨기면 홈의 연관 집계도 줄어들 수 있습니다.

## 본인 비밀번호 변경

관리자·팀장·팀원 모두 사이드바의 **내 비밀번호 변경** 또는 상단 사용자 이름 → **내 계정**에서 변경할 수 있습니다. 현재 비밀번호와 새 비밀번호를 두 번 입력합니다. 현재 비밀번호로 재인증한 뒤 로그인한 본인의 비밀번호만 변경합니다. 새 비밀번호는 8자 이상이며 Firebase 프로젝트의 추가 비밀번호 정책도 적용됩니다. 비밀번호는 Firestore·백업·로그에 저장하지 않습니다. 현재 비밀번호를 잊었으면 로그인 화면의 재설정 메일 기능을 사용합니다.

Firebase 저장 상태는 사이드바 하단의 일반 배치 영역에 표시합니다. 로그아웃 버튼을 덮는 고정 배치를 사용하지 않습니다. 사이드바를 접으면 상태 점과 PW 버튼으로 축약하고 하단 공간이 부족하면 내부 스크롤로 표시합니다.

## Storage 미사용 운영

현재 구성은 Firebase Storage를 사용하지 않습니다. Storage SDK를 불러오거나 저장소를 초기화하지 않으며 첨부파일 업로드도 차단합니다. `firebase.json`에도 Storage 배포 설정을 포함하지 않습니다. 요금제 업그레이드나 Storage 규칙 설정 없이 로그인과 Firestore 업무 데이터 기능을 사용합니다. 서비스별 사용량 한도는 Firebase 콘솔에서 관리합니다.

- 사진·PDF·일반 첨부파일의 새 업로드는 사용할 수 없습니다. 문서 제목·분류·설명 등 데이터는 저장할 수 있습니다.
- 백업에 첨부파일이 있으면 제외할 건수를 먼저 표시합니다. 확인한 경우에만 첨부를 제외하고 업무 데이터를 복원합니다. 취소하면 서버에 쓰지 않습니다.
- 원본 JSON 백업 파일은 수정하지 않습니다. 첨부 PDF는 원본 백업에 남아 있으므로 별도로 보관하세요.
- 복원 시 파일명 등 메타데이터와 첨부 제외 표시를 유지합니다. PDF 방식의 월 추진업무는 제목을 보존하고 직접 입력 방식으로 전환합니다. 본문이 비어 있으면 첨부 제외 안내를 넣습니다.
- 브라우저에서 작성한 내용을 PDF로 출력하거나 내려받는 기존 기능은 그대로입니다. 서버 파일 업로드와는 별개입니다.

`storage.rules`와 `storage.cors.json`은 이전 구성 참고 파일이며 현재 설정에서는 사용하거나 배포하지 않습니다.

## 로그인·새로고침

인증 세션 확인 중에는 로그인 폼 대신 별도 확인 화면을 표시합니다. 세션이 없다고 확인된 경우에만 로그인 폼을 열고 유효한 세션이면 마지막으로 보던 메뉴로 돌아옵니다. 마지막 메뉴는 사용자별 브라우저 세션에 저장하며 로그아웃할 때 지웁니다. 현재 역할에서 접근할 수 없어진 메뉴는 홈으로 이동합니다.

로그인에서는 먼저 볼 메뉴에 필요한 데이터만 기다립니다. 나머지 메뉴와 변경이력은 뒤에서 불러옵니다. 아직 데이터가 준비되지 않은 메뉴에는 로딩 상태를 표시하며 빈 데이터로 오인하지 않도록 합니다. 백업 복원과 기존 PC 데이터 가져오기는 전체 조회가 완료된 뒤 진행합니다.

한 번에 도착한 여러 기록은 묶어서 반영하고 스냅샷마다 화면을 한 번 갱신합니다. 실제 서버 응답시간과 네트워크 지연은 별개이며 이번 작업에서는 실제 로그인 소요시간을 측정하지 않았습니다.

## 저장과 충돌

- 각 업무·일정·사업 등을 별도 문서로 저장합니다. 데이터베이스 전체를 한 문서에 덮어쓰지 않습니다.
- 각 기록의 버전을 트랜잭션에서 확인합니다. 다른 사용자가 같은 기록을 먼저 변경하면 후속 저장을 중단합니다.
- 왼쪽 아래에 서버 저장 상태가 표시됩니다. 실패한 변경사항은 화면 메모리에 유지됩니다. **미저장본 다운로드**로 복사한 뒤 서버 내용으로 되돌리거나 연결 복구 후 다시 저장할 수 있습니다. 브라우저 종료 경고를 무시하면 미저장 변경사항이 사라집니다.
- 여러 기록의 일괄 삭제와 백업 복원은 기록별로 처리합니다. 중간 실패 시 앞서 저장된 기록은 반영되어 있을 수 있습니다. 상태창에서 남은 변경사항을 확인하세요.
- 로그인 정보는 브라우저 세션 동안 유지합니다. 업무 데이터는 영구 로컬 캐시에 저장하지 않습니다. 로그아웃할 때 메모리와 화면의 데이터를 지웁니다.

## 검증

```bash
node --test tests/sync-engine.test.cjs tests/adapter.test.cjs
```

동시 수정 충돌·다른 기록 보존·저장 중 추가 변경·통신 실패 재시도·삭제 충돌·로그아웃 정리 및 Firebase 어댑터의 로그인/저장/원격 갱신을 모의 SDK로 검사합니다. 어댑터 검증에서는 실제 페이지의 렌더러도 빈 DB로 실행합니다.

`tests/browser-smoke.cjs`는 Playwright 브라우저 검증용입니다. 실행 환경에 Playwright와 Chromium이 필요합니다. 이번 작업 환경에서는 Chromium 다운로드가 네트워크 제한으로 차단되어 브라우저 검증은 실행하지 못했습니다. 모의 테스트는 실제 Firebase 서비스·보안 규칙의 에뮬레이터 검증을 대신하지 않습니다. 운영 적용 후 관리자 로그인 → 업무 등록 → 다른 PC 조회 → 팀원 로그인과 본인/타인 기록의 권한을 확인해야 합니다.

서버 비밀키나 서비스 계정 JSON은 저장소에 추가하지 않습니다. 웹용 Firebase 설정값은 클라이언트에 포함되며 실제 접근 권한은 게시된 Firebase 규칙으로 제한합니다.
